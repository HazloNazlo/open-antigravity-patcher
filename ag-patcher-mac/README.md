# ag_patcher — патчер Antigravity для macOS

Локальный патчер региональных ограничений **Antigravity.app** и **Antigravity IDE.app**
для свежих версий на Apple Silicon. Без ключей, без сторонних сервисов, без перехвата
трафика: только локальные правки в файлах приложения.

Проверено на: Antigravity 2.31.2, Antigravity IDE 2.6.0, CLI agy 1.5.6 (arm64).

---

## Что делает

| Цель | Что правится |
|---|---|
| `manager` | `Antigravity.app/…/bin/language_server` — снимает клиентский гейт `hasValidAuth` (arm64/x64) |
| `ide` | `Antigravity IDE.app/…/out/main.js` — снимает гейт допустимости тира и переводит онбординг на `standard-tier` |
| `hub` | `~/.gemini/bin/agy` — бэкенд IDE (`agy --hub`), отдельный бинарник с отдельным гейтом |
| `cli` | `~/.local/bin/agy` — CLI agy |

Плюс ко всему:

* **откат чужого «анлокера»** — если в бинарник вшита подмена `https_proxy` → `AG_LS_PROXY`
  (делают «разблокировщики» с ключом в Telegram), она возвращается обратно. Иначе приложение
  шлёт запросы в несуществующий локальный прокси и выдаёт
  «There was a network issue connecting to the server, please try again».
* **переподпись бандла** — после правки печать codesign рвётся, и macOS считает приложение
  повреждённым (улетает в корзину). Переподпись идёт изнутри наружу, с сохранением
  entitlements и Hardened Runtime, плюс `disable-library-validation` (иначе Electron
  получает SIGKILL на проверке библиотек).
* **обход App Management** — macOS запрещает писать внутрь чужого `.app`. Если запись
  запрещена, патчер собирает исправленную копию бандла и подменяет приложение целиком.
* **журнал правок** — `~/Library/Application Support/ag_patcher/journals/`. Хранит
  смещения и байты, а не копию 180-МБ бинарника, поэтому откат точный и почти мгновенный.

Ничего не перехватывается, токены никуда не уходят, сеть не трогается.

## Использование

```bash
python3 ag_patcher.py status              # что сейчас в системе
python3 ag_patcher.py patch --target all  # пропатчить всё
python3 ag_patcher.py doctor              # диагностика: сеть, сервисы, подписи
python3 ag_patcher.py restore --target all# откатить по журналу
python3 ag_patcher.py resign --target all # только переподписать
python3 ag_patcher.py stop-confeden       # остановить сторонний «анлокер»
```

Только стандартная библиотека Python 3.9+. Зависимостей нет.

### После обновления Antigravity

Обновление перезаписывает бинарники — патч слетает. Лечится одной командой:

```bash
python3 ag_patcher.py patch --target all
```

Расширение IDE само скачивает `~/.gemini/bin/agy` (v1.5.x) — этот файл тоже нужно
перепатчить после каждого такого обновления, поэтому патчите всегда `--target all`.

## Как это устроено (для тех, кому интересно)

### Гейт `hasValidAuth` (Go-бэкенды)

`authclient.(*PersonalAuthValidator).Validate` кладёт в `AuthResult` байт `hasValidAuth`
по смещению +8. Пока байт нулевой, клиент уводит выполнение в ветку «аккаунт не допущен».

arm64 (Apple Silicon):

```
ldrb  w3, [x0, #8]          ; читает hasValidAuth
tbz   w3, #0, <skip>        ; флаг нулевой — прыгаем мимо успешной ветки
...
stp   x3, x4, [x0, #0x60]   ; успешная ветка: запись токена
```

Правка: `mov w3,#1` + `strb w3,[x0,#8]` — флаг принудительно True, переход убран,
выполнение всегда идёт по успешной ветке.

x64 — аналогично: `cmp byte [rax+8],0` + `je` → `mov byte [rax+8],1` + `nop` + `nop`.

Сигнатуры ищутся регулярками по коду инструкций, а не по смещениям, поэтому переживают
пересборку. При неоднозначном совпадении паттернер отказывается угадывать и не трогает файл.

### Гейт IDE (main.js)

В Antigravity IDE 2.6.x проверка переехала в `confirmUserForService`:

```js
const r = n?.allowedTiers?.find(l => l.id === "free-tier");
let i = "", a = "";
n?.ineligibleTiers?.forEach(l => { l.tierId === "free-tier" && (i = l.reasonMessage, a = l.validationUrl) });
const s = !!r || !i, o = await …;      // ← вот гейт
if (s) { await …onboardUser("free-tier", t); … }
```

Две точечные правки:

1. `const s = !!r || !i` → `const s = !0` — клиент больше не проверяет допуск к `free-tier`.
2. `onboardUser("free-tier", t)` → `onboardUser("standard-tier", t)` — сервер отклоняет
   онбординг в `free-tier` для аккаунтов вне поддерживаемых регионов, а `standard-tier`
   принимает.

Результат: `Auth state changed to: success` → `signedIn` в `logs/<сессия>/auth.log`.

Для IDE 2.5.x остаётся запасной вариант — принудительная «внутренняя» ветка входа
(`resetIsTierGCPTos(), …isGoogleInternal` → `true`). На 2.6.x он **не работает**:
приложение уходит в модальное окно и hangs на старте.

### Переподпись

Порядок важен: сначала вложенные Mach-O и вложенные бандлы, потом сам `.app`.
`--deep` не используется — он подписывает вложенный код в неопределённом порядке
и оставляет печать бандла разорванной.

Entitlements берутся из текущей подписи (`codesign -d --entitlements - --xml`) и
возвращаются в новую. Без этого Electron падает: теряется
`com.apple.security.cs.allow-jit`, без которого V8 не может JIT.

### App Management

macOS запрещает процессу писать внутрь `.app`, установленного другим разработчиком.
`sudo` не помогает — проверка на уровне AMFI. Поэтому патчер сначала пробует запись
на месте, а при отказе собирает исправленную копию бандла в `/private/tmp` и подменяет
приложение целиком (`rename` внутри тома). Оригинал остаётся рядом как
`<Имя>.app.agbak-<дата>`, его можно удалить.

### Проверка синтаксиса

После правки JS проверяется `node --check`. Если синтаксис сломан — файл
автоматически возвращается в исходное состояние.

## Диагностика «There was a network issue…»

Это сообщение генерирует `language_server`, когда не может достучаться до Google.
Две разные причины:

1. **Подмена прокси** — в бинарник вшит `AG_LS_PROXY` вместо `https_proxy`, а локальный
   сервис «анлокера» выключен. Лечится откатом подмены (`patch` делает это сам).
2. **Протухший сокет VPN** — в логе видно
   `read tcp 10.8.1.2:50112 -> 172.217.117.4:443: read: can't assign requested address`.
   Это не патч: после смены адреса в туннеле (AmneziaWG и подобные) старые соединения
   отваливаются. Помогает перезапуск приложения после смены VPN-соединения.

Проверить, что сеть жива: `python3 ag_patcher.py doctor`.

## Ограничения

* Только macOS на Apple Silicon (проверено). x64-сигнатура в коде есть, но не тестировалась.
* Привязка к структуре конкретных сборок: если Google перепишет логику допуска,
  паттерны перестанут совпадать — паттернер ничего не сломает, а сообщит
  «гейт не найден».
* Серверная проверка региона не обходится: патч снимает только клиентский гейт.
  Если сервер прямо отказывает в выдаче tier — это видно по сообщению
  «not eligible … not currently available in your location».
* `standard-tier` онбординг принимается не у всех аккаунтов — тогда сработает
  запасной путь через `free-tier`.
